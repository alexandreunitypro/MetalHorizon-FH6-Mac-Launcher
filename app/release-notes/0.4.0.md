**Early alpha.** MetalHorizon for Forza Horizon 6 on Apple silicon Macs: the Xbox / Microsoft Store edition and, new, the Steam edition. Built from your reports (thank you to everyone who opened an issue).

### Steam edition: fixed from the ground up
Every problem in the Steam report is addressed, following Highball's method:
1. **Steam's installer downloads again.** `cdn.steampowered.com` answers some networks with the wrong certificate and the store's web page (`curl: (60) ... no alternative certificate subject name`). MetalHorizon now uses Valve's other servers (Akamai, media, Cloudflare, Fastly), one after the other, and checks that it got the real installer.
2. **Blackwell Engine Steam 1.1 has its 32-bit half.** Steam's installer and client are 32-bit programs; 1.0 had no `lib/wine/i386-windows`, hence `syswow64\ntdll.dll error c0000135`. 1.1 is built for i386 and x86_64 with mingw-w64 gcc, as Highball builds it (llvm-mingw is known to break Steam's sign-in).
3. **Steam's window draws.** It opens with DXMT (Highball's build, which allows the swap chain Steam's browser uses across processes) and with sync off. It used to be black, or to abort on `setDisplaySyncEnabled` under D3DMetal. Measured on an M5 Pro with macOS 27.2: Steam installs in about 30 seconds, updates itself, and shows its sign-in window.
4. **Steam keeps its sign-in.** Play no longer kills the prefix with `wineserver -k`. Steam is stopped cleanly with its own `-shutdown`, and only when needed.
5. **No more sync conflicts.** Every program in the prefix gets the sync mode of what is already running, so no more `msync_init Failed bootstrap_look_up`.
6. **The path check passes.** Steam and the game live in a prefix MetalHorizon manages, and the game starts from `C:\Program Files (x86)\Steam\steamapps\common\ForzaHorizon6`, short enough for "Installation path is too long".
7. **The game starts through Steam**, from a silent client with msync (`steam.exe -silent -applaunch 2483190`), so it gets its Steam ticket (no more E:0-0-L-8 or "Welcome, Player").
8. **Use an existing bottle**: point the Steam prefix at a Highball, CrossOver or Whisky bottle that already has Steam and the game.

### Controllers
9. **GameInput in the engine.** Forza Horizon 6, like every GDK game, reads controllers through GameInput, and Wine's gameinput.dll was a stub. Engine patch 0012 implements it (interfaces v0, v1 and v2) on top of XInput. It turns on at Play when a controller is connected (Options › Controllers: Automatic, Always On, Off).
10. **SDL2 in both engines**: Xbox pads directly; PlayStation (DualShock 4, DualSense), Switch Pro, 8BitDo, HORI, PowerA and generic pads with an Xbox layout. Wheels go through DirectInput.
11. **Controllers panel**: the pads macOS sees, live, and how each one reaches the game. Tools › Test Controllers in Wine opens Wine's own panel.

### Logs and diagnosis
12. **One folder per run** (`~/Library/Logs/MetalHorizon/sessions`). The game's output is always kept: it used to go to `/dev/null`, which is why some reports had nothing in them. Each run's header records the versions and the settings that decide the graphics stack. Old runs are rotated out.
13. **A faster, cleaner Activity view**: it reads only the new lines, hides MoltenVK's 150-line dumps, and offers Errors only, a search field, and the game's own output.
14. **Automatic diagnosis**: after each run, more than 30 known problems are recognized (curl 60, c0000135, black Steam window, msync, Neural Engine, path length, E:0-0-L-8, xodus-service, FH205, FHE21, concrt140...). Each one comes with its cause and what to do, in plain words.
- **Game package put back by itself** (Xbox): when the game files were moved without their hidden package `.xodus-streaming.msixvc` (xodus then stopped with a bare "No such file or directory"), MetalHorizon finds it in the usual places (Desktop, ~/FH6, Downloads, Documents) and moves it back into the game folder when it opens, a simple rename on the same disk, leaving a link at the old place.
15. **Checks before Play**: macOS 27, Rosetta (with a button that copies the command), memory (8 GB warning), app run from Downloads or still quarantined, a game folder whose files moved, iCloud folders, free space, Steam for macOS still running.
16. **Export Diagnostics**: one zip on the Desktop for a GitHub issue, with logs, setup and crash summaries, and tokens, e-mail addresses, Xbox IDs, Steam IDs and account names removed. **Report an Issue** opens a pre-filled issue.
- **Crash reports to the developer**: when a run crashes, MetalHorizon shows the error message itself (Wine's exception and the first frames of its backtrace, which now go to the log instead of Wine's "Program Error" box, or a macOS crash report), what it recognized, and **Send to the Developer**: the report (versions, engine series, game build, options, the run's header) and a zip of the logs, secrets removed. It asks right after the crash, or at the next launch (Options › Crash Reports: Ask Me, Send Automatically, Never).
17. **Relaunch after D3DMetal's Neural Engine failure** (`com.apple.appleneuralengine Code=26` at start-up, which depends on timing): MetalHorizon relaunches the game by itself, twice at most.

### Options and tools
18. **Options menu**: Metal HUD, MetalFX upscaling (DLSS in the game), a frame cap (30/40/45/60), Controllers, relaunch on failure. **Tools menu**: run the checks again, Export Diagnostics, Report an Issue, logs and Wine prefix in Finder, Wine configuration, Open and Stop Steam.
19. **Game update of 3 November 2026**: Microsoft's own concrt140 and C++ runtime are loaded first (Wine's crashed the game a minute in), and Steam's overlay is kept out of the game.
- **MetalHorizon updates itself** from this version on: at each launch it checks the releases, and a newer version installs by itself once nothing is running (checked against `SHA256SUMS` and its signature; the previous app goes to the Trash, and comes back if the new one does not start). Settings, sign-in, engines and the game are kept. MetalHorizon › Check for Updates… does the same on demand.

### MCP server for AI assistants
20. **25 tools, resources and prompts.** It can diagnose the last runs, explain a pasted error, list the known problems, read and search the logs, read crash reports, check the network, check the components (32-bit half, SDL2, GameInput, DXMT), and read Steam's status, the controllers and the Wine prefix. It can also show what Play would run, change the settings (with the user's agreement), open or stop Steam, and export the diagnostics. Resources expose the setup, the known problems and the last runs' logs. Prompts cover diagnosis, setup, Steam, controllers, performance and a GitHub report. Help › Connect an AI Assistant shows how to plug it into Claude.

### Get started
1. Unzip `MetalHorizon-0.4.0.zip` and move **MetalHorizon** to Applications. It is not notarized yet: the first time, right-click it › **Open** › **Open**.
2. Choose your edition at the top of the window. MetalHorizon installs its engine and Apple's D3DMetal by itself (accept Apple's licence when it asks).
3. **Xbox**: Sign In with Microsoft, choose a short folder such as `~/FH6`, then Download from Xbox. **Steam**: Install Steam, Open Steam and sign in there, then install Forza Horizon 6 from your Library.
4. Click **Play**. Quit the game from its own menu (Xbox: wait about 30 seconds, the cloud save uploads).

### Known
- **Steam edition**: tested up to Steam's sign-in on one Mac, **not in game**: the project has no Steam copy. Please report back; Diagnosis › Export gives everything needed.
- **Controllers through GameInput**: tested in Wine with a test program (devices, readings, callbacks), not yet with a pad in the game.
- Frame pacing (short freezes under Rosetta), black near foliage. Highball's native arm64 engine (FEX) avoids those freezes at 30 fps; it is not in MetalHorizon yet.
