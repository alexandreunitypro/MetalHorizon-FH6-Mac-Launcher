**Online play, DLC, controllers, sign-in and Steam's first start (issues #13, #15, #16, #17, #18, #19).** MetalHorizon updates itself to this version when it opens, and installs the new engines by itself.

### Online play: matchmaking, events and races (issue #18)
- **The cause**: before matchmaking, Forza Horizon 6 opens its game socket for IPv4 and IPv6 at once and sets two IPv4 options on it (`IP_DONTFRAGMENT`, `IP_TTL`). Windows accepts that; macOS refuses it, so the game closed the socket, tried two other ports the same way, and gave up: no session found, joined events dropped at once.
- **The fix**: prsloan's patch from Highball (highball-engine pull request #40) sets the IPv6 counterparts macOS does accept. It is in all three engines: **Blackwell Engine 1.2** (Xbox and Game Pass on D3DMetal), **steam-1.2** (Steam) and **Blackwell Engine Native 1.2**.
- **Checked on this Mac, without the game**: the 26-check socket test from the same pull request opens the socket the way the game does. Engines 1.1 fail 7 of its checks; all three 1.2 engines pass all 26, the native one through FEX and Highball's signed loader as you get it.
- Turn **cross-play on** in the game's settings: Highball's players found online play needs it.

### Xbox and Game Pass: VIP, Car Pass and expansions (issue #18)
- **The cause**: the game asks the Xbox service for a **licence token**, which it hands to Forza's servers to show what your account owns: the VIP membership, the Car Pass, a Premium edition's expansions. It also asks about its own licence and the Store catalog. The service did not know these requests ("Unimplemented" and "Unknown magic" in its log) and closed the connection, so none of that showed.
- **The fix**: xodus-service answers them now, the way Ferestre's service does (the runtime in our engines is Ferestre's): licence tokens signed with the game's own Xbox token, the game's licence, the Store catalog (the in-game marketplace lists the game's add-ons: 34 in the US catalog), and who is signed in. It answers for Forza Horizon 6 only, read from the game's own MicrosoftGame.config.
- The hundreds of "Failed to read magic: early eof" lines in xodus-service.log were the game closing each finished request, not a fault: they are no longer written as errors.
- At the first Play after the update, macOS asks once more to let the new **xodus-service** use your Xbox sign-in in the Keychain: choose **Always Allow**.

### Steam: the game never starts after Steam's 5-minute wait (issues #16, #17)
- **The cause**: before a game's first start, Steam can stop and wait for you to dismiss a notice ("a controller is recommended", or Steam Input for a PlayStation pad). The silent Steam client MetalHorizon starts the game with shows no window, so it waited for good, and the game then reported E:0-0-L-8.
- **The fix**: before it starts Steam, MetalHorizon records these notices as seen in Steam's own settings, as Steam does once they are shown (Highball found this). It also reads Steam's own log while it waits: if Steam still waits on a notice, it stops Steam, records it and starts it again at once instead of waiting 5 minutes. A licence agreement or a cloud-save choice still needs you: Open Steam, answer it once.
- When Steam still cannot start the game, the run's log now carries Steam's own lines about the launch (from its `console_log.txt`), not just "msync: up and running".

### Controllers: a PS5 (DualSense) or third-party pad seen but doing nothing (issue #15)
- **The cause**: the pad reached the game through XInput, but MetalHorizon's GameInput reported it with its own maker (Sony, PowerA, PDP…). The game then took it for a raw HID device and read it the HID way, which this GameInput does not provide: connected, and nothing happened.
- **The fix**: every pad is now reported to the game as what XInput makes of it, an Xbox One controller (its own name stays). All three 1.2 engines carry it. Controllers must be on in Settings › Controllers (Automatic turns them on when a pad is connected at Play).

### Sign-in: Xbox's real reason instead of "Initialization Failed" (issue #13)
- When Xbox refuses the account itself, signing in again cannot help, and that was all MetalHorizon offered. It now reads Xbox's own reason (its XErr code) before Play and in the logs, and opens the page that fixes it: **no Xbox profile yet** (Create Xbox Profile), **Xbox terms not accepted**, **child account not in a Microsoft family**, **family settings blocking online play**, **play-time limit**, **proof of age**, **country or region**, **account suspended**. Then Sign In Again.

- And when Microsoft refuses this Mac's **device ticket** (it ages, or gets revoked), every Xbox request failed and signing in again did not help, since the account was never the problem. The Xbox service now renews the device ticket by itself from the device key the sign-in stored, and tries again (Ferestre does the same). Nothing is written to the Keychain for it, so no new macOS window appears mid-game.

### Game updates: E:43-1b-4 "Invalid Profile" and empty online sessions (issue #19)
- On a Mac nothing updated the game, while Forza's servers want the current build: an older game finds no online session, and once your cloud profile was saved by a newer build (on an Xbox, a PC or in the cloud) it says **Invalid Profile (E:43-1b-4)**.
- Before Play, MetalHorizon now asks Microsoft which version is current (at most every 6 hours) and, when yours is older, offers **Update the Game**: it downloads only what changed, into the same folder.

### Also
- **"concrt140… unimplemented function" (issue #19)**: Blackwell Engine Native 1.1 and 1.2 have that function. Checked in the published files: both entry points run real code. A report written before the engine update finished can still show the old crash; if it shows on 1.0.4, please send the diagnostics.
- **E:43-1b-4 right after a crash**: update the game if MetalHorizon offers it; then quit the game from its menu and wait about 30 seconds before closing MetalHorizon, so the cloud save uploads as the game closes.
